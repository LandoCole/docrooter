Jev's tokens are exact, from the API. Jev answers one question per call with a probability for every option, so each heading costs a call or two, each carrying its own option list: a 400-heading annual report is about 250,000 input tokens, a cent at Jev's $0.042 per million (output is free). On held-out documents, tagging first and letting the rules decide named the type less often (82.5–90%) than reading the document first, so the demo opens on Read, then tag. Tags are capped at 400 headings per document, and 11% of the labelled headings, mostly the notes of the longest annual reports, fall past it.

A note on the numbers. The 113 gold documents span 8 types (annual reports, fact sheets, prospectuses, government reports, contracts, court opinions, research papers, standards). The doc-type rules were revised after looking at them, so treat the gold columns as development numbers; the held-out set is the clean measure. The section labels (2,194 headings, every depth) were written by Claude annotators for evaluation only; a third are none, a heading with nothing to normalise.

How it works

A context ladder. doc-rooter reads a PDF or Markdown file into its section tree, then renders it at four rungs, each adding one thing: the headings (title, counts, the contents), then key terms, then the opening sentences, then the whole text, within a 16,000-token prompt. Every section gets its own view at the same rung: its path, its title and, higher up, its key terms and lead.

Section tags that mean something. A tag normalises what a heading means, so the same kind of section can be found across documents however each one words it: "Statement of financial position" and "Consolidated balance sheets" are both a balance sheet; "Audit opinion" and "Report of independent registered public accounting firm" are both the auditor's report. A heading with nothing to normalise (an introduction, a summary, Part II) is tagged none. Every heading is tagged, at any depth, so the statements nested under Item 8 are found too.

Two approaches. Tag, then decide tags the sections first; rules over the tags (a balance sheet plus management's discussion means a financial report) decide the type when they can, and Jev chooses only among the types left. Read, then tag lets Jev read the document view and name the type first, then tags the sections the same way.

A decision model. Jev answers each question with a probability for every option instead of generating text, so the answer is always one of the options, the confidence is usable, and every call's tokens are exact.

Why

Sending a model the whole document is the easy default, and it's expensive at volume: a 200-page filing is 100,000 tokens before the model reads a word of the question. I built doc-rooter to find the least a model needs to see. For the document's type, the title and the contents were about as good as anything richer. More context mostly gave the model more to be distracted by.

doc-rooter is the next step after my document classifier, which names a financial document's type from a short overview in one question to Jev. doc-rooter takes the same idea further as a standalone package: it reads a PDF into its section tree, tags every section as well as the document, lets the sections decide the type, works with any model you plug in, and measures what each extra piece of context buys.
